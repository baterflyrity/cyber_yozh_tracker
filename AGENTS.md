# Инструкции для coding agent

Перед изменением кода обязательно прочитай все спецификации в каталоге `spec/`:

- `spec/SPEC.md` — функциональные требования, API, права доступа, тесты и Definition of Done;
- `spec/ARCHITECTURE.md` — разделение моделей, доменной логики, selectors и API endpoints;
- `spec/LOCAL_DEVELOPMENT.md` — актуальный локальный запуск, Compose, seed и команды тестирования;
- `spec/COMPOSE_E2E_RECOVERY.md` — диагностика и восстановление Docker Compose / Playwright E2E;
- `spec/FRONTEND.md` — адаптивный UI и темы;
- `spec/DOCUMENTATION.md` — требования к README и дополнительной документации.

Все спецификации, кроме этого файла, должны находиться в `/spec/`. Не создавай копии `SPEC.md` или других документов требований в корне.

## Рабочий процесс

- Сначала изучи текущий `git status`, структуру проекта, `compose.yaml`, оба Dockerfile, entrypoint, `pyproject.toml`, `uv.lock`, E2E-тесты, CI workflow и README.
- Для задачи по Compose E2E следуй `spec/COMPOSE_E2E_RECOVERY.md` и `spec/LOCAL_DEVELOPMENT.md`. В текущем агентском окружении репозиторий доступен по `/app/cyber_yozh_tracker`; перед работой подтверди `pwd` и корень Git.
- Не предполагай, что у контейнера есть GUI-браузер. Docker, Docker Compose и доступные порты предоставлены окружением; проверь их командами и запускай headless Chromium в предназначенном для этого E2E-контейнере Playwright.
- Сначала воспроизведи исходную ошибку и сохрани логи. Не начинай с предположительной правки и не маскируй ошибку тестов.
- Не пересоздавай проект с нуля, не сбрасывай пользовательские изменения и не удаляй постоянные volumes без понимания последствий. Для диагностики используй отдельное имя Compose-проекта.
- Не ослабляй assertions, не удаляй падающие проверки и не заменяй браузерные тесты `curl`-запросами.
- После изменения конфигурации выполняй `docker compose config`, сборку и настоящий запуск Compose E2E с передачей exit code тестового сервиса вызывающей команде.
- Проверь повторный запуск и идемпотентность demo seed. Проверь, что тестовые данные изолированы и тесты не зависят от порядка запуска.
- Сохраняй скриншоты, трассировки, логи и результаты падения в `test-results/`, если инфраструктура позволяет.
- Синхронизируй README и спецификации с реально работающими командами. Не заявляй об успешной проверке, если соответствующая команда действительно не завершилась успешно.

## Завершение

В отчёте перечисли первопричину сбоя, диагностические данные, изменённые файлы, точные команды и exit codes, сводку тестов, результат Docker Compose, а также оставшиеся ограничения. Отдельно сообщи, запускался ли Chromium в E2E-контейнере и были ли фактически выполнены браузерные тесты.
